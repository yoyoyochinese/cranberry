## F1-1（major）: back edge が 2 本のループを見逃し、D55-1 のループ遅延の勘定が崩れる

**場所:** `src/cranberry/core/pipeline.py:403-446`（検査 (2)）。D55-1 と `core/delay.py:8-13` の説明は、「フィードバックが閉じる所で必ず 1/f_sim がちょうど 1 回加わる」ことを前提にしている。

**何が問題か:** 検査 (2) が確かめているのは「どの閉路も `delay_buffer` を通る」ことと「どの back edge も閉路を作る」ことだけで、1 つの閉路にある back edge（1 サンプルの遅れ）の数は数えていない。`delay_buffer` を書き手より前に置くと（`plant → sensor → d → pid → act`）、`pid → d` と `act → plant` の 2 本が back edge になる。検査は通り、閉ループの遅延は `tau_s + 2/f_sim` になる。プリセットは D55-1 に従って `tau_s = τ_L − 1/f_sim` と置くので、ループ遅延が気づかれないまま 1/f_sim 長くなる（refD の 1 MHz では 1 µs、τ_L = 5.7 µs の 18%）。

**根拠:** `reviews/scripts/f1_two_back_edges.py`（同じブロックで、`tau_s = 0` のまま並び順だけを変えた）。

```
A correct order : builds OK, plant first moves at sample 1
B misordered    : builds OK, plant first moves at sample 2
extra closure delay in B: 1 sample(s) = 1.0 us (D55-1 assumes 0)
```

今のプリセットは影響を受けていない（`reviews/scripts/f1_count_back_edges.py`: refD_nominal の 1 ループ、refA の 2 ループとも back edge は 1 本）。並び順を変えるだけで崩れる不変条件なので major とした。

**修正の提案:** 検査 (2) で、閉路ごとに back edge の最小本数を数える（0-1 BFS。スクリプトの `cycle_back_edges` がそのまま使える）。2 本以上なら `PipelineCheckError` にする。意図して許す場合は、明示のフラグと、記録への実効ループ遅延の書き出しを条件にする。D55-1 に「閉路あたり back edge はちょうど 1 本（ビルド時に検査）」と書き加える。

## F1-2（major）: f_sim の収束確認がモデルそのものを変えてしまう（式が古いまま、機器のレートが保たれない）

**場所:** `src/cranberry/runner/convergence.py:190-197`。説明（14-16 行）は「`sweep.expand` を通すので `tau_s = τ_L − 1/f_sim` のような式は再評価される」と書いているが、そうなっていない。`core/rates.py:112-120` の `with_f_sim` も、読み込み時に解決済みの値を書き換えない。さらに `convergence('f_sim')` は `with_f_sim` の `keep_rate`（機器の更新レートを保つ仕組み、`rates.py:19-23`）を使っていない。

**根拠:** `reviews/scripts/f1_fsim_expr_stale.py`

```
refD_nominal (f_sim = 1 MHz): tau_s = {'dsc1.latency': 3.2e-06}
  expand x2: tau_s = 3.2e-06 (unchanged), tau_s + 1/f_sim = 3.70 us vs 4.20 us → 60 kHz で 10.8°
  expand x4: tau_s = 3.2e-06 (unchanged), 3.45 us vs 4.20 us → 16.2°
refA (20 MHz): dl1/dl2 tau_s = 9.5e-07 (unchanged), ×2 で 0.975 us vs 1.000 us（0.54°）
```

`expand` の後でも refD の `dsc1.pid`・`dsc1.dac`・`dsc1.sup` は `rate_div = 2` のままなので、f_sim = 2 MHz では DSC1 の PID が 1 MHz で更新される（DSC1 の仕様 p.2 は 500 kHz）。refD の −180° は約 60 kHz にあるので、10.8° のずれと保持の遅延の半減は、まさに比べたい量（残差 σ、ロックの成否）を動かす。PLAN §6.4 の「f_sim を 2 倍・4 倍にして変化が許容幅の 1/3 以下」は、このままでは数値の収束ではなく別のモデルどうしを比べることになる。refD の `gamma_coh`（`refD.yaml:333`、項 −4π²h₀τ²·f_sim/2）も 1 MHz の値のまま残る。D63-9（`sweep.expand` が解決済みの `!expr` を再評価しない）と根は同じだが、その結果として §6.4 の収束確認（F1 の受け持ち）が成り立たなくなることは記録されていない。D63-1 の refA の収束の主張（20 MHz で ≤ 0.006 dB）は、遅延の 25 ns のずれ（2.5%）を含んだ比較だった。

**修正の提案:**
1. `convergence('f_sim')` と `with_f_sim` は、解決前の木（入力の文書と overlays）に `run.f_sim_hz` を上書きしてから**解決し直す**。`RunSpec` に `!expr` を解決前の形で残すか、`config_input` から読み直す。D63-9 の修正と一緒に行う。
2. 機器のレートで動くブロックを、仕様の中で宣言できるようにする（例: リーフの `rate_hz:`、または `run.keep_rate: [...]`）。`convergence` は `scale_rate_divs(keep_rate=...)` を必ず通す。
3. （別案・併用可）D55-1 の勘定をフレームワークに移す: `delay_buffer` に `tau_total_s`（τ_L）を渡し、ブロックの中で 1/f_sim と明示的にモデル化した遅延を引く。式の再評価に頼らずに済む。
4. VT を足す: refD を f_sim ×2 にしたとき、`tau_s + 1/f_sim` と PID の物理的な更新レートが変わらないこと。

## F6-1（major）: 線形の端数遅延（D57-7）、とくに逆向き伝搬の差の過小評価

**場所:** `src/cranberry/path/segments.py:264-278`（小区間の時刻への補間）、`src/cranberry/path/beams.py:76-86`（`_interp`。光源の位相と区間の出口から観測点までの遅延）。

**閉じた式:** 線形補間 y = (1−μ)x[n−k] + μ x[n−k−1] の応答は |H|² = 1 − 2μ(1−μ)(1 − cos ωh)。したがって、定常な駆動 x の 1 ステップの自己相関を ρ₁ とすると

  Var(y)/Var(x) = 1 − 2μ(1−μ)(1 − ρ₁)、  ΔS/S = −4μ(1−μ) sin²(πf/f_sim)

ρ₁ = 0（白色）が D57-7 の 2μ(1−μ)。厳密な（帯域制限した）遅延では分散は変わらない。

**根拠 1（閉じた式の確認、実際のブロック）:** `reviews/scripts/f6_fracdelay.py` part 1（L = 1 m、8 MHz、μ = 0.0196）

| ρ₁ | 測定した分散の比 | 閉じた式 |
|---|---|---|
| 0.0 | 0.96167 | 0.96159 |
| 0.5 | 0.98087 | 0.98080 |
| 0.9 | 0.99611 | 0.99616 |

**根拠 2（逆向き伝搬。F6 の存在理由である「相殺の計算」）:** part 3・part 4。L = 63 m（τ = 308 ns）、N_sub = 20、小区間ごとに独立な白色駆動。前向きのビームは x = L、逆向きのビームは x = 0 で出る（VT-37 V6 と同じ観測量）。表は S_D（線形補間）/ S_D（厳密な遅延）。

| f_sim | f/f_N = 0.10 | 0.25 | 0.50 | 0.75 | 0.95 | 帯域内の D の分散（白色 / 1/f²） |
|---|---|---|---|---|---|---|
| 1 MHz | 0.992 | 0.952 | 0.820 | 0.631 | 0.466 | 0.625 / 0.786 |
| 4 MHz | 0.991 | 0.948 | 0.821 | 0.682 | 0.600 | 0.711 / 0.841 |
| 20 MHz | 0.985 | 0.903 | 0.685 | 0.501 | 0.105 | 0.620 / 0.920 |

時間領域（実際の `segment_phase` → `beam_assembler`、4 MHz、2¹⁹ サンプル、Welch）で測った比は、f/f_N = 0.25、0.50、0.75、0.95 で 0.935、0.819、0.691、0.596。予測は 0.948、0.821、0.682、0.600 で、よく一致する。VT-37 V6 は f_sim = 1 GHz で小区間の遅延が整数サンプルになる場合だけを試しているので、プリセットの領域（1–20 MHz、遅延がサンプル間隔より短い）でのこの偏りは、どのテストにも現れない。

**影響:** 物理的に関係する帯域（音響・振動。≲ 100 kHz）では f/f_N ≤ 0.2（1 MHz）なので、誤差は約 3% 以下。一方、f_N まで白色の駆動で、帯域内の残差の分散（指標 (ii) の成分）をまとめて出すと、30–40% 小さく出る。BandLedger は f_N より上しか足さないので、f_N 付近に穴が残る。

**修正:** 下の「D57-7 への推奨」を参照。最低限: (a) 下の規則を D57 に加える、(b) part 4 の構成（サンプル間隔より短い遅延の領域）を VT-37 に加え、既知の補間の応答を固定する。

## F6-2（minor）: 区間の位相を 2 回補間している

**場所:** `path/segments.py`（出口までの (n−j−½)δ）と `path/beams.py:145`（出口から観測点までの τ_after）。

**何が問題か:** 1 つの小区間の雑音が観測点に届くまでの遅延を、2 段の線形補間 (1−μ₁+μ₁z⁻¹)(1−μ₂+μ₂z⁻¹) で作っている。合計の遅延を 1 回補間するより振幅の落ちが大きく、μ₁ + μ₂ が 1 を越えると差がとくに大きい。白色の駆動での分散の比:

| μ₁, μ₂ | 2 段 | 1 段（合計の遅延） |
|---|---|---|
| 0.02, 0.02 | 0.924 | 0.923 |
| 0.1, 0.3 | 0.513 | 0.520 |
| 0.3, 0.4 | 0.402 | 0.580 |

**修正の提案:** `segment_phase` の小区間のリングから、観測点までの合計の遅延（to_exit_j + τ_after）で直接読む。リングは max(k) + 2 に伸びるだけ。`beam_assembler` の `hist_<seg>` のリングは要らなくなる。

## F6-3（minor）: `arg t_pol` の折り返しで位相が 2π 跳ぶ

**場所:** `path/beams.py:292-295`（kernel）、`326-329`（参照）。

**何が問題か:** `phi += atan2(t.imag, t.real)` をサンプルごとに計算するので、`t_pol` が負の実軸を横切ると `beam.phi` が ±2π 跳ぶ。`lock_error` は折り返さない（「制御器は連続な位相の誤差を見る」、`path/locks.py:3`）ので、`lock.err` も 2π 跳ぶ。dc_fringe のように誤差を cos/sin でしか使わないセンサには影響しないが、誤差を線形に使うブロックや、記録した系列の PSD には段差が入る。SMF の `u0: haar` ＋ drift（D62-2）では横切りは普通に起こる。

**修正の提案:** ビームごとに前のサンプルの arg をスロットに持ち、差を (−π, π] に折り返して足していく（連続な unwrap）。または、「`beam.phi` は 2π を法としてだけ意味を持つ」ことを契約に書き、線形に使うブロックを検査する。

## F1-3（minor）: 多重レートの保持の実効遅延が規則に書かれていない

**場所:** `core/rates.py:3-9`（保持の意味）、D61-2（`dsc1_explicit_delay_s = 1.5 µs` に「500 kHz の ZOH 1 µs」を含める）。

**根拠:** `reviews/scripts/f1_loop_delay_response.py`: 間引き r で保持した系列の、位相について平均した LTI 部分の群遅延は、r = 2 で 0.5 サンプル、r = 4 で 1.5 サンプル、すなわち (r−1)/2 サンプル。連続時間の ZOH（r/2 サンプル）との差の半サンプルは、VT-24 test 10 のコメントのとおり、下流の 914 を `zoh` で離散化したことによる界面の遅延として入っている。下流が `bilinear` なら、この半サンプルは消える。

**修正の提案:** `rates.py` の説明と D55-1/D61-2 に「保持は (r−1)/(2 f_sim)。D/A の界面の 1/(2 f_sim) は、下流の連続時間ブロックの離散化の方式（zoh）による」と書く。(r−1)/2 を固定する単体テストを足す。

## F1-4（minor・潜在）: コンパイル済みループのキャッシュの鍵の衝突

**場所:** `core/compile.py:89-103`（`_canon`）。

**根拠:** dict ではないオブジェクトは `repr` で比べられる。中央の 1 要素だけが違う 5000 点の 2 つの `Table` で、`_canon({'tab': t1}) == _canon({'tab': t2})` が `True` になった（numpy の省略表示）。同じ qualname のラムダを 5 回作っては捨てると、`_canon` は 1 種類しか出なかった（id の再利用）。

**影響:** 今は、`Table` や callable から計算した値をカーネルに閉じ込めるブロックは見つからない（区間の係数は P に入る）。ただし D55-3 の規則はこれらを構造パラメータとして許しているので、将来のブロックが閉じ込めると、掃引や seed の集団で前の点のカーネルを黙って使う。

**修正の提案:** dataclass はフィールドを再帰的に正準化し、配列は内容のハッシュにする。callable はキャッシュの項目に強い参照を持たせて id の再利用を防ぐ（または、callable を含む構造ではキャッシュしない）。

## F1-5（minor）: `DrawBuffer` の消費の検査がない

**場所:** `core/rng.py:161-170`。

**何が問題か:** `refill` は前の区切りの消費の数を確かめずに `idx = 0` に戻す。条件付きで乱数を使う（または per_step を取り違えた）カーネルでは、使われなかった乱数が区切りごとに捨てられ、どの乱数がどのステップに当たるかが区切りの位置で変わる。G11 の「チャンク長でビット単位で同じ」が、規約だけで守られている状態になる。

**修正の提案:** `refill` で `idx == 前回の count` を確かめ、違えば例外にする（コストはほぼない）。

## F1-6（minor）: `thiran1` の適用範囲

**場所:** `core/delay.py:105-109`。

**根拠:** `f1_loop_delay_response.py`: refD の `tau_s = 3.17 µs`（1 MHz）での位相の誤差は、100 kHz で linear +0.22°、thiran1 +0.49°。250 kHz では +3.7° と +6.3°。D = 0.3 µs では 100 kHz で linear +0.21°、thiran1 −0.34°。D < 0.5 では a = (1−d)/(1+d) が 1 に近づき（D = 0.01 で a = 0.980、インパルスの 99% に 35 サンプル）、ナイキストで振動する。F6-1 の part 3 では、サンプル間隔より短い光の遅延に thiran1 を使うと、f_N 付近を 1.5–4.6 倍に過大評価した（1 MHz）。

**修正の提案:** 両方のプリセットが使っているとおり、linear を標準とする。`thiran1` は「D ≥ 0.5、振幅を 1 に保つことが目的のとき」と説明に書き、D < 0.5 では CHK の警告を出す。

## F1-7（minor）: 記録の間引きにエイリアス除去のフィルタがない

**場所:** `runner/run.py:319-341`（`Recorder`、`rate_div = decim`）。

**何が問題か:** decim ごとの点の標本化なので、記録した系列の平均と分散には偏りがないが、PSD と、記録した系列から作るゼロスパンのトレース（D63-2）のばらつきには、f_rec/2 より上の成分が折り返す。refA では f_sim = 20 MHz、decim = 100（f_rec = 200 kHz）で、位相のジッタは MHz まで広がっている。VBW = 100 Hz のフィルタは、折り返して低周波に来た成分を一部通してしまう。

**修正の提案:** 説明に明記する。スペクトルに使う記録には、任意で区間平均（boxcar・CIC）の間引きを選べるようにする。ESA の扱い（WP-B5/I1）と合わせて確認する。

## D57-7 への推奨（線形の端数遅延の補間）

**結論:** **linear のまま**にする。thiran1 にも補正係数にもせず、使い方の規則と、テスト・台帳での扱いで制御する。

1. **偏りの大きさ（F6-1 の閉じた式）:** 補間 1 段ごとに Var 比 = 1 − 2μ(1−μ)(1−ρ₁)、ΔS/S = −4μ(1−μ) sin²(πf/f_sim)。誤差はナイキスト付近に集中し、**物理的な周波数 f を固定すれば、f_sim を上げると ∝ (f/f_sim)² で 0 に近づく**。
2. **f_sim との関係（`f6_fracdelay.py` part 2）:**
   - 白色の駆動: 不足 ≈ 2τf_sim（μ ≪ 1）で、f_sim とともに**増える**。μ が 1 を回り込むので単調でもない（63 m・1 小区間の例: 26% → 43% → 47% → 36% → 16% → 28%、1–40 MHz）。f_N まで白色の駆動では、全分散の f_sim の収束は原理的に得られない。
   - OU（角周波数 f_c）: 不足 ≈ 4πτf_c(1−μ) で、f_sim にほとんど依らず小さい（1 m では 100 kHz で 0.29%、10 kHz で 0.03%。63 m・1 小区間では 1 MHz で 12%（f_c = 100 kHz）、1.6%（10 kHz））。
   - レーザーの位相（`beam_assembler` の光源のリング）は離散のランダムウォークで、同じ 1 サンプル内の 2 つの遅延の差は Δφ = 2πτ δν[n] と**帯域内で厳密**になる（白色 FM で (2πτ)²h₀ が f_N まで平ら）。T05 §3.5 と refD の `gamma_coh` の −4π²h₀τ²f_N の項と整合しているので、変更は要らない。
3. **thiran1 にしない理由:** 振幅は 1 に保たれるが、ナイキストで位相が −π に固定され、D < 0.5 では極が −1 に近づく。逆向き伝搬の差では、1 MHz で f_N 付近を ×1.5–4.6 に過大評価し、4–20 MHz では過小評価する（part 3）。小区間 × ビームごとに IIR の状態も要る。
4. **規則（D57 に追加する提案）:**
   - (a) 時間ループから出す PSD は f ≤ f_N/4 の範囲だけを結論に使う（逆向き伝搬の差で ≤ 5%）。1% が要るときは f ≤ f_N/10。D57-6 の「f_N は雑音の角周波数・ピークより十分高く」を、「駆動の ρ₁ が 1 に近い（1 − ρ₁ ≲ 0.05）」と定量化する。
   - (b) f_sim の収束（§6.4）は、白色に近い駆動を含む構成では、全分散ではなく**固定した物理周波数での PSD** で比べる（F1-2 の修正が前提）。
   - (c) 帯域内の残差の全分散が要るとき（指標 (ii) の成分で駆動が f_N まで平らな場合）は、BandLedger に補正 ΔVar = ∫₀^{f_N}(|H_exact|² − |H_lin|²)S df を足す。μ はビルド時に分かり、S は `bands()` の宣言から分かるので、T05 §3.5 の σ²_oob と同じ形のオフラインの表で計算できる。全体の分散を割り戻す補正係数は使わない（低周波を過大にする）。
   - (d) F6-2 の 2 段補間を 1 段にまとめる（白色で最大約 0.2 の差がなくなる）。
   - (e) VT-37 に、サンプル間隔より短い遅延の領域の試験（part 4 の構成、4 MHz・63 m・N_sub = 20）を足し、補間の既知の応答（表の値）に ±3% で一致することを固定する。

## 確かめて正しかったもの

- **ループ遅延の勘定（D55-1）:** back edge が 1 本のループでは、閉ループの遅延は `tau_s + 1/f_sim` になる（`f1_two_back_edges.py` の A）。refD と refA のプリセットのループはすべて back edge 1 本（`f1_count_back_edges.py`）。光の伝搬遅延（アクチュエータ → 検出器）は放出時刻の評価で自動的に入り、`tau_s` には含まれない（T10 §3.2 の「x_a から取り出し点までの遅延がループ遅延に加わる」と整合）。
- **端数遅延の算術（`core/delay.py`）:** 整数（1e−9 以内）・linear・thiran1 の差分方程式、`freq_response`、リングの長さ k + 2、リングの読み書きの意味。ループで使う周波数（≤ 100 kHz）での位相の誤差は、どちらの方式も 0.5° 以下（`f1_loop_delay_response.py`）。
- **パイプラインの検査:** 遅延 0 のループの拒否、読む前に書かれていない順序の検出、並列の分岐の書き込みが素であることと兄弟の分岐を読まないこと（D55-2）、単位のタグ、名前の重複。Stack の展開 `c1 >> (a1 | (c2 >> …))`、Stack ≡ 展開（ビット単位）、線形の範囲で Stack ≡ 並列形（VT-44）。
- **compiled == reference:** VT-44 に加え、`f1_chunk_multirate_path.py`（rate_div 1/2/3/5 の混在、per_sub の白色駆動、逆向きのビーム、J_nr 付きの jones 区間、周波数オフセット、thiran1 の delay_buffer）で最大相対差 1.3e−16。
- **チャンク長に対するビット単位の一致（G11）:** 同じスクリプトで、チャンク [1]、[7, 4096, 3]、[4097]、[5000, 11] のすべてがビット単位で一致。VT-F2 の 2 件も通過。
- **乱数の流れ:** 名前の SHA-256 から鍵を作り、作る順序に依らない。`substream` は消費しない。`_lgs` は複数のバッファにそれぞれ substream を使っている（同じ Generator を共有して区切りで交互に引く問題はない）。間引きのある `DrawBuffer` の補充数 `n_steps_in` は `should_step` と整合。
- **放出時刻（conv §7、T05 §3.5）:** φ_b(t) = φ_src(t − τ_b) + Σ ψ（各小区間を通る時刻）。小区間の中心を出口の (n−j−½)δ 前に通る。逆向きは同じ小区間を逆の順に読む。周波数の伝搬依存を重ねて数えていない。周波数オフセットの静的な位相 +2π f_off τ_b は conv §4 の符号（A = |A|e^{i(φ − Ω_sh t)}）と β₁ΩL = Ωτ_g に一致する。
- **逆向き伝搬:** 一様な駆動では前向きと逆向きが厳密に打ち消し合う（両者は同じ遅延の集合 {(j+½)δ} を読むため）。分布した駆動の S_D = 2S[1 − sinc(2πfτ)] は、整数遅延の領域で再現される（VT-37 V6）。per_sub の雑音は (1 − κ)·N·S で、N_sub に依らない（`noise/mech.py:19-21`）。
- **符号（conv §4・§9）:** 係数 > 0 で ψ が増え、`beam.phi += ψ` となる（長さ・温度とともに増える）。ロックの誤差は Σ c_b φ_b − 設定点。逆向きは Jᵀ（転置で、共役ではない）。J_nr は前向き N·U、逆向き Uᵀ·N（D62-1。往復で Faraday の回転が 2 倍、相反の回転は打ち消す）。速い軸の係数は c_slow − K_T·L（K_T < 0 で Δψ_b = K_T·L·ΔT < 0、dψ_fast/dT = L(C_T + |K_T|)）。DGD は速い軸が早く着く（D62-6）。
- **駆動の密度（D61-1）:** `uniform`/`per_sub` の重み 1/N、`subs` は 1/N を列挙した小区間に、`point` は 1 を 1 つの小区間に置く。`DrvTarget` は δψ·N_sub/(hi − lo) を書き、Σ drv/N_sub = δψ になる。topology の配置とアクチュエータのスロットの形が合わなければ、`_check_driver_slots` が TypeError にする。
- **トグル（チェック項目 7）:** `phase` をオフにすると ψ ≡ 0、`group_delay` をオフにすると名目の τ、`emission_time` をオフにすると τ = 0（f_off の位相も 0）、`polarization` をオフにすると行列の積をとらない（VT-37 V11、unit/path）。
- **FFT（チェック項目 5）:** `fft_agrawal` を Gaussian の解析解と比べ、conv §8 の e^{+iΩT} に 3e−15 で一致（逆符号では 2.6 ずれる）。`psd_onesided` は片側（Parseval: 分散 0.4886 に対して ∫S df = 0.4881）。
- **レイアウト・キャッシュ:** Haar の U0 などの乱数で決まる静的な値は、スロットの初期値として持っていて、カーネルには閉じ込めていない（D55-3 に適合）。区間の係数は P に入る。
- **保護リスト（チェック項目 10）:** ランナー、State、光路ごとの位相モデル、遅延バッファ、factory、入れ子の合成、トグルのどれも削られていない。
- **該当しない項目:** チェック項目 (3)（2 倍の因子）は片側 PSD だけが該当し、正しい。(8)（損失・帯域の二重登録）のうち F6 が受け持つ `register_loss_paths`・`register_band_beams` は 1 ビーム 1 経路で、重複はない。(9)（値の出典）はフレームワークのコードには該当しない。
